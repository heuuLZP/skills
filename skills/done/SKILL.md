# Done（最后一棒）

默认使用用户语言。本技能负责从"开发完成"到"接测出结果"的完整最后一棒：审阅与提交在本技能内由 fresh-reviewer 完成（应在用户浏览器验证通过后触发）。push 与接测须经过一次集中确认门。

## 不可破坏的边界

- push 与接测必须先经过单门确认（结构化选择工具展示完整清单），一次确认覆盖门内列出的全部动作，门后不再逐步询问。
- **多会话并行时只处理本任务改动**：审阅提交范围以本任务涉及的文件与模块为准；工作区中属于其他会话的改动不暂存、不提交、不清理，仅在汇总中一句说明存在范围外改动。
- 不自动创建分支：当前分支不是交付分支（如 f-/bg- 前缀）时停止，提示用户先建分支。
- **rebase 冲突默认自动解决**：逐文件判定——他人改动与本次改动不重叠的各自保留（并集）；同文件冲突按语义保守合并，不丢双方意图。全部解决后必须通过快速完整性验证才算完成。仅在无法安全判定语义的冲突上停止并列出该文件。
- 只接测测试环境，且只使用 Mars 状态查询返回的合法接测动作；不碰生产/灰度。

## 1. 审阅提交（限定本任务范围）

1. 确定本任务改动范围：本会话任务涉及的文件与模块清单；范围外改动按边界规则保留不动。用户明确声明**交付全部待处理改动**（如"两个任务都做完了一起交付"）时，范围为全部待处理改动，按职责分批提交；用户明确指定只交付部分任务时，以指定任务的范围为准。
2. 范围内无未提交改动、远端也无待 push 提交 → 直接进入第 3 步检查是否只需接测；完全无事可做则汇报并停止。
3. spawn `fresh-reviewer` 审阅提交（spawn 提示中传入范围清单），等待报告；报告含"遗留决策"时用结构化问题转问用户，拿到答复后把决策发回该子代理继续。
4. 记录仓库、当前分支名；`git fetch` 后记录 ahead/behind。

## 2. 远端同步

- behind：rebase；冲突按边界规则自动逐文件解决，全部解决后继续；无法安全判定语义的冲突 → 停止并列出该文件。
- rebase 与冲突解决完成后做快速完整性确认（增量 typecheck + 按文件 lint，委派 light-runner），失败 → 停止并报告，不进入确认门。
- diverged 且无法安全 rebase → 停止说明现状与建议。

## 3. 姊妹仓库检查

映射：fe-partner-portal↔bff-partner-portal、fe-partner-operation↔bff-partner-operation（按 `../` 同级目录推断，不存在则跳过并说明）。

- 检查姊妹仓库同名分支：工作区改动或未 push 的 ahead 提交视为"有配套改动"。
- 有 → 纳入本次流程（同样执行第 1、2 步检查）；无 → 单仓库流程。

## 4. 单门确认

先用第 5 步的 Mars 状态查询拿到接测数据，再弹出一次结构化确认，展示：

- 每个仓库：分支、将 push 的提交数（ahead）、最新提交标题。
- 每个应用：将从 Mars 查询得到的接测应用名与环境。

选项：`确认推送并接测 / 取消`。取消则不做任何远端动作。

## 5. Mars 接测（逐仓库）

1. 先用 Mars 分支状态查询（分支名）；无上下文且未指定模块时，普通与 ASIOT 状态工具都查，按真实返回对象与 available_actions 路由，不按产品标签硬编码。
2. 接测参数只取自查询返回的合法 to_test 动作；用户已指定测试环境则沿用，否则优先 env_code 为 yktest 的项。
3. 接测后必须用本次返回的 pipeline_id 轮询该实例结果，不得以最新一次流水线替代。
4. 失败：用该行 stages 动作中的 pipeline_id 查阶段 → 查 FAILED 阶段日志 → 摘要根因并汇报；不自动重试接测。
5. 结果 state=submitted 仅表示提交，须轮询到终态。

## 6. 汇总

- push：仓库/分支/提交列表。
- 接测：应用/环境/流水线终态/关键日志结论（如失败）。
- 遗留：未解决的冲突（如有）、验证失败、需要用户决策的事项。
