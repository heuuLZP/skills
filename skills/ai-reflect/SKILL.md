# AI Reflect — AI 协作复盘

扫描 Claude Code 与 Codex 的近期对话历史，从四个维度分析人机协作质量，生成结构化复盘报告。

## 为什么做这件事

AI 是高效的工具，但长期使用容易形成依赖——不自己思考就把问题丢给 AI，不做验证就采用 AI 的方案。这些习惯会削弱独立思考和解决问题的能力。定期复盘能帮你保持清醒，确保 AI 是工具而非拐杖。

## 工作流程

### 1. 确定分析范围

解析用户指定的时间范围，默认最近 7 天。支持"3天"、"2周"、"1个月"等表述。

计算截止时间：`now - time_range`。

### 2. 扫描对话文件

```bash
python3 <skill-directory>/scripts/scan_sessions.py --days 7 --output /tmp/ai-reflect-sessions.json
```

先根据当前 `SKILL.md` 的位置解析 `<skill-directory>`，不要假设当前工作目录就是 skill 目录。根据用户要求把 `--days` 替换为实际天数。脚本统一扫描：

- Claude Code：`~/.claude/projects/**/*.jsonl`
- Codex：`~/.codex/sessions/**/*.jsonl`

读取脚本输出的标准化 JSON。只分析 `sessions[].messages` 中的真实用户消息和助手文本。脚本会排除系统/开发者提示、工具调用与结果、审批转录、附件以及子代理重复记录。

**数据量控制**：脚本对超过 200 条消息的 session 保留前 10 条、后 10 条和中间均匀采样的 20 条；session 超过 20 个时优先保留消息数最多的 session。

### 3. 逐 Session 分析

对每个 session，先判断主题类别：

| 类别 | 判断依据 |
|------|----------|
| 编码 | 涉及代码编写、修改、调试 |
| 学习 | 用户在询问概念、原理、教程 |
| 问题排查 | 排查 bug、错误、异常 |
| 架构设计 | 系统设计、方案讨论、技术选型 |
| 其他 | 不属于以上类别 |

然后按四个维度标注行为模式：

#### 思考深度

看用户消息中是否体现：
- 提问前已做过分析或尝试（比如"我试了 X 但 Y 不行"）
- 问题是否具体且有上下文（vs 模糊的"帮我做 X"）
- 是否追问、质疑 AI 的回答
- 是否要求 AI 解释原理而非只给结果

#### 职责分配

看任务执行中：
- 用户是否自己做了一部分（比如先写了代码再让 AI 优化）
- 是否让 AI 教方法而非直接要结果
- 关键决策（架构、方案选择）是用户做还是 AI 做

#### 信源多样性

看用户是否：
- 要求 AI 查阅官方文档
- 要求对比多个方案
- 提到与同事讨论、请教专业人士
- 写测试验证 AI 的方案

#### 能力趋势

首次分析时建立基线。后续分析时：
- 读取上次报告（`~/.agents/data/ai-reflect/reports/` 下最新文件）
- 对比各维度评分变化
- 标注趋势箭头：↑ 改善 → 持平 ↓ 退化

### 4. 生成报告

将报告保存到 `~/.agents/data/ai-reflect/reports/YYYY-MM-DD.md`，使用以下模板：

```markdown
# AI 协作复盘报告
> 分析周期: YYYY-MM-DD ~ YYYY-MM-DD
> 生成时间: YYYY-MM-DD HH:MM
> ⚠️ 本报告由 AI 分析生成，存在自我参考的局限性，建议作为参考而非定论。

## 概览
- 分析会话数: X
- 总交互轮次: X
- 来源分布: Claude Code X次 | Codex X次
- 主题分布: 编码 X次 | 学习 X次 | 排查 X次 | 架构 X次 | 其他 X次

## 思考深度: [🟢/🟡/🔴] + 一句话评分
[2-3 个具体观察，引用对话中的实际例子（脱敏），说明判断依据]

## 职责分配: [🟢/🟡/🔴] + 一句话评分
[2-3 个具体观察]

## 信源多样性: [🟢/🟡/🔴] + 一句话评分
[2-3 个具体观察]

## 能力趋势: [基线建立 / ↑ / → / ↓]
[首次：建立基线。后续：与上次对比变化]

## 建议
[3-5 条具体可执行的建议，基于本次分析的实际发现，不要泛泛而谈]
```

评分标准：

| 等级 | 含义 |
|------|------|
| 🟢 | 状态良好，无需特别调整 |
| 🟡 | 有改善空间，值得关注 |
| 🔴 | 存在明显问题，建议重点调整 |

### 5. 输出摘要

报告保存后，在对话中给出简要结论：
- 总体评分（四维一撇）
- 最值得关注的一个点
- 报告文件路径

## 注意事项

- 引用对话内容时注意脱敏，避免暴露敏感信息（密码、token、私密内容）
- 评分要有依据——每个判断都应来自对话中的实际证据，不要凭感觉给分
- 建议要具体可执行，不要"多思考"这种空话，而是"在提问前先写下你已经尝试过的 2-3 种方法"这样的具体建议
- 分析本身是 AI 在做，有自我参考的局限，报告中必须注明这一点
- 不把标准化会话 JSON 或原始对话复制进报告目录；临时文件分析完成后删除
