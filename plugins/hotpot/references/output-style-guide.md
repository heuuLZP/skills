# Output Style Guide

> 所有 hotpot 原子 skill 共享的输出规范。

## 核心原则

产物是给人看的，不是给机器解析的。人的认知预算应该花在业务、架构和风险判断上，不花在解析平铺文本上。

## 输出规则

1. **结论先行**：先给判断、摘要、阻断项，再展开依据。
2. **结构化优先**：列表、表格、分节优先；段落超过 5 行就拆。
3. **渐进展开**：先给 30 秒能扫完的概要，再给细节。
4. **可视化优先**：涉及流程、关系、状态、数据流时，用 Mermaid。
5. **少贴代码**：文档只贴签名、类型或关键片段，不贴大段实现。

## Mermaid 使用

| 表达内容 | 推荐形式 |
|---|---|
| 流程 / 顺序 | `flowchart` |
| 模块交互 | `sequenceDiagram` |
| 状态流转 | `stateDiagram-v2` |
| 数据流向 | `flowchart LR` |
| 依赖关系 | `flowchart LR` |

## 自检清单

- [ ] 顶部有摘要或总判定。
- [ ] 没有超过 5 行的段落。
- [ ] 流程、关系、状态、数据流有图。
- [ ] 没有贴超过 10 行代码。
- [ ] 30 秒能扫到核心结论。
