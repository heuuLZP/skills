# Review Checklist

> 用于 `hot-plan-review` 和 `hot-check` 的就地审查清单。

## Plan Review 维度

| 维度 | 检查问题 |
|---|---|
| Requirement 覆盖 | plan/spec 是否偏离 `requirement.md` 的目标、范围、约束和阻断澄清点 |
| Spec 覆盖 | plan 是否覆盖 spec 的全部行为、规则、边界和验收场景 |
| 业务入口覆盖 | entry-bundle 中每个业务入口是否有明确计划落点，单入口 review 是否只处理相关范围 |
| 共享规则一致性 | shared rule 是否在多个入口采用同一实现口径，局部规则是否被误提升为模块行为 |
| 问题归属 | 未确认项是否被计划擅自定案，跨 Case 信息是否被错误用于关闭当前问题 |
| 澄清门禁 | 是否在阻断问题未确认时生成计划；已删除问题区的结论是否已沉淀并保留来源 Case |
| 可落地性 | 文件职责、数据流、状态流转是否足够明确 |
| 依赖方向 | 是否存在循环依赖、层级倒置、跨边界调用 |
| 架构决策门禁 | 高影响架构变更是否有用户确认的决策摘要；缺失时是否阻断 |
| 架构决策一致性 | plan 是否遵守摘要中的边界、约束、取舍和演进方式，是否新增未覆盖的跨边界依赖 |
| 交互基础设施 | 拖拽、滚动、请求、缓存、竞态是否使用成熟方案或已有模式 |
| 验证点 | 每个关键场景是否有验证方式 |
| P19 | 是否默认新建了不必要的单测 |
| 注释/JSDoc | 复杂导出函数、非显然状态机、竞态处理是否要求注释 |

## Completion Check 维度

| 维度 | 检查问题 |
|---|---|
| 需求范围 | 实际改动是否仍符合 `requirement.md` 的目标、范围和约束 |
| 用例闭环 | primary flow、edge case、failure case 是否都有结果 |
| 业务入口闭环 | 整模块检查是否逐 entry 给出结果，单入口检查是否覆盖该 entry 与相关共享规则 |
| 共享规则闭环 | shared rules 是否统一落地，接口依赖是否在受影响入口得到验证 |
| Spec 合规 | 行为契约、业务规则、边界是否被满足 |
| Plan 对照 | 文件职责、状态、数据流是否按 plan 落地 |
| 架构决策闭环 | 实现是否遵守 plan 中的架构决策依据，是否新增边界、共享依赖或运行风险 |
| 验证证据 | 命令输出、应用走查、已有测试是否支撑结论 |
| 偏离记录 | 与 spec/plan 的偏离是否说明原因和影响 |

## 不检查

- 不做泛泛代码质量 review。
- 不排查新 bug；发现 bug 线索时建议使用 `superpowers:systematic-debugging`。
- Codex 中不自动起 review 子代理。
